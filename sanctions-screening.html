Sanctions List Screening API: OFAC, UK, EU, UN & US lists

On Apify Store

Answers "is this company, vessel or person sanctioned?" for one or many names, against the official OFAC SDN and non-SDN lists, the US Consolidated Screening List (Commerce Entity List, Denied Persons, State lists), the UK Sanctions List, the EU financial sanctions list and the UN Security Council list. Every answer says which lists were checked and how current they were, and every match links to its official source. Built for AI agents doing KYB, compliance or procurement checks, and for people who need a quick, sourced screen. It also checks crypto wallet addresses exactly against the addresses OFAC lists (XBT, ETH, USDT, TRX and more), e.g. before an agent pays.

Input fields

FieldTypeMeaning
namesarrayCompany, vessel or person names to check, one per entry, as plain text, e.g. ["Sovcomflot", "Novo Nordisk A/S", "Vladimir Putin"]. Legal forms (Ltd, LLC, GmbH, PJSC), accents, punctuation and word order are ignored. Up to 200 names; each name gives one result row and one charge; repeats are screened once. Give names, addresses or both.
addressesarrayCrypto wallet addresses to check, one per entry, e.g. ["0x7FF9cFad3877F21d41Da833E2F775dB0569eE3D9"]. Matched exactly against the wallet addresses the lists publish (OFAC SDN: XBT, ETH, USDT, TRX and more); EVM 0x and bech32 bc1 addresses ignore case, others must match as written. Up to 50; each checked address gives one result row and one charge, same price as a name (an address no selected list publishes wallets for is answered free). Give names, addresses or both.
countrystringCountry of the party you are screening, as an ISO 3166 alpha-2 code or English name, e.g. "RU" or "Russia". It never hides a match: listings that name other countries move to the end and get country_match false. Empty = no country ranking.
entityTypestringOnly return listings of this type, e.g. "organization". Default "any". Listings whose type the list does not state (the US Commerce and State lists) are always kept.
minScoreintegerLowest similarity score (0-100) that counts as a match, e.g. 85 (default). 100 = same name after normalisation; 90-99 = small spelling differences or the name inside a longer listed name; lower values find more variants and more false positives. Range 50-100.
listsarrayWhich lists to check, any of "ofac_sdn", "ofac_consolidated", "us_csl", "uk", "eu", "un", e.g. ["ofac_sdn", "uk"]. Default (or empty) = all six. The price is the same for any number of lists.

Sources, licence and limits

Is this legal advice or a compliance decision? No. It is a screening aid. Fuzzy name matching produces false positives (a namesake) and can miss a party listed under a spelling or script it doesn't recognise. Review every match against the official entry (source_url) before acting, and use your own judgement or counsel for decisions. Only the official publications are authoritative (for the EU, the Official Journal).

The CSL's Treasury sub-lists are skipped because the same entries come from OFAC directly.

What is not covered? National lists of other countries, PEPs (politically exposed persons), adverse media, ownership (the OFAC 50% rule: companies owned by listed parties are often not listed themselves) and EU sectoral or vessel annexes outside the financial sanctions list are not covered.

How fresh is it? Each run uses the lists as published at most 1 hour earlier; older copies are downloaded again. lists_checked shows each list's own publish date. Agencies publish on their own schedule (OFAC and the CSL often daily, the UK and EU when designations change).

Why is listing_date null for OFAC? OFAC's standard XML doesn't include designation dates (only its 110 MB "enhanced" file does). Check the OFAC entry page in source_url.

Personal data? The lists name individuals. This Actor serves only per-name screening results (at most 5 listings per name, no bulk export) for sanctions compliance, and keeps only the fields needed to confirm or rule out a match. See LEGAL.md.
