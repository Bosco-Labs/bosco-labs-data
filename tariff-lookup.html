Input fields

FieldTypeMeaning
codestringA US HTS code (8 or 10 digits, e.g. "8712.00.15" or "8712001510") or a UK commodity code (10 digits, e.g. "8712003010"). Dots and spaces are ignored. 4 or 6 digits (or a UK code that is not declarable) fail for free with a list of the codes under it. Empty = use query instead. Charged as one code-lookup.
querystringPlain product description, 2-200 characters, e.g. "bicycle" or "cotton t-shirt". Charged as one code-search however many candidates come back.

originCountrystringISO 3166 alpha-2 code of the country the goods come from, e.g. "CN" or "DE". UK: preferential rates, additional duties and VAT are filtered to measures that apply to that country. Sources, licence and limits

Is this a classification? No. A code lookup returns what the official tariff says for the code you give. A search returns the official search engine's hits (for the US, ranked by us: lines under a heading that matches your words first). Neither is a binding ruling; the importer or declarant remains responsible. Get a binding ruling from U.S. CBP or an HMRC Advance Tariff Ruling.

Does it give the total duty I will pay? No. It gives the rates the tariff publishes. It does not apply rules of origin, quotas, end-use relief, valuation or the duty calculator.

US: are Section 301, 232 and IEEPA tariffs included? Only where the HTS data links them to the line: Chapter 99 footnotes on the line and Chapter 99 lines whose text names the code. Duties applied through Chapter 99 note lists (most Section 301 China lists, Section 232 derivatives, IEEPA reciprocal tariffs) are not linked per line in the HTS data, so every US row says so in warnings. Check HTS Chapter 99 for goods of China and for steel, aluminium and autos.

How is UK read? Live from HMRC's production Trade Tariff API with Bosco Labs' own developer-portal credentials (OAuth 2.0); you need no HMRC account. A UK lookup takes about 1-2 s.

UK: what is left out? Import controls and prohibitions (licences, certificates) are counted in warnings, not listed. Excise and some company-specific anti-dumping rates depend on conditions and come back with rate: null; follow source_url. Export measures, quotas' balances and Northern Ireland (XI) tariffs are not included.

How fresh is it? Each run reads the current US HTS edition (named in edition) live. UK responses are cached for up to 24 hours, as HMRC recommends ("It is recommended you cache requests for 24 hours"): within a run on Apify, and per server process in the Bosco Labs API.

Where does the data come from, and may I reuse it? USITC's HTS REST API (a U.S. Government work, public domain in the US) and HMRC's UK Trade Tariff API (Open Government Licence v3.0: keep the attribution text when you republish UK data). USITC's disclaimer says the site is "only intended to be general summary information to the public. It is not intended to provide legal advice". HMRC's terms say "If you use the Trade Tariff APIs, you must follow published guidance and usage limits", which we do: managed OAuth credentials on HMRC's production host, the 24-hour cache, retries with backoff and a 20-second limit. Neither forbids automated access within those limits.

Which codes work? US: 8- and 10-digit HTS lines (description searches skip Chapters 98 and 99, which are special provisions). UK: declarable 10-digit commodity codes; anything shorter lists the declarable codes under it for free.
