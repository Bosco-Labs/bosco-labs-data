Sources, licence and limits

Where does the data come from? OSV.dev, Google's open vulnerability database, which collects the GitHub Advisory Database, the PyPA, Go and RustSec databases, OpenSSF malicious-package reports and more. OSV decides whether your exact version is in an affected range (we never re-implement version rules). Exploit status comes from the CISA KEV catalog (downloaded fresh every run); for a CVE/GHSA id we add FIRST's EPSS score and NVD's record.

Is a clean answer charged? Yes, once we know the package is real. "No known vulnerabilities in OSV.dev" is the answer you asked for and costs $0.005 like any other. Nothing is charged when the input is invalid, the package or version does not exist, the id is unknown or OSV.dev does not answer.

Does it check that the package or version exists? Yes, whenever OSV.dev has no advisory for it: the name (and version) is looked up in the registry index (deps.dev for npm, PyPI, Maven, Go, crates.io, NuGet and RubyGems; Packagist for PHP). Not found = the run fails with "check the spelling" and costs nothing. Releases from the last few hours may not be indexed yet. If the index itself is down, you get the answer with the warning "Existence not verified". When OSV does have advisories, the package is reported even if it was removed from its registry (for example a malicious package).

How fresh is it? Live: OSV.dev, KEV, EPSS and NVD are queried on every run. OSV imports new GitHub advisories within minutes to hours; brand-new CVEs can take a day to appear.

How is safe_version chosen, and what are its limits? We take the fixed versions from the advisories, keep those above your version, and ask OSV which of them have no known vulnerability. If all are hit by other advisories, we follow those advisories' fixed versions (three rounds). It is not a scan of every release: a clean version that no advisory names as "fixed" is not proposed, and it ignores semver majors (check breaking changes yourself). Versions are ordered numerically; pre-release tags are not ranked precisely. Without a version there is no safe_version: the newest fixed version could be older than what you run.

Why is cvss_score sometimes null? OSV records carry CVSS vectors, not scores. We compute the CVSS v3 base score from the vector (FIRST's formula); v4-only advisories keep the vector and a null score. In CVE mode, nvd.cvss_score is NVD's own score.

What is not included? Operating-system packages (Debian, Ubuntu, Alpine, Red Hat), container images and transitive dependencies: pass each package you care about. Advisories from sources whose licence forbids commercial reuse (Chainguard/Wolfi, CC BY-NC-ND) are omitted, with a warning naming them.

Can I republish the results? Keep the attribution text. Licences, checked first-hand on 6 Nov 2026: - OSV.dev lists a licence per source (osv.dev data sources). We use only: GitHub Advisory Database, PyPA, Go and OSS-Fuzz data (CC BY 4.0, which requires credit and noting changes: each item names its source_db and license), RustSec (CC0 1.0), OpenSSF Malicious Packages (Apache 2.0) and NVD-converted CVE records (NVD is a US government work in the public domain; CVE content is used under MITRE's CVE Terms of Use, whose copyright line is in attribution). - CISA KEV: "The KEV database is distributed under the Creative Commons 0 1.0 License" (license.txt); no CISA endorsement is implied. - FIRST EPSS: "Attribution is requested when EPSS data is used in publications or products" (EPSS FAQ); FIRST's Services Terms license distribution for vulnerability disclosure, incident response or preventative cybersecurity uses. - NVD: This product uses the NVD API but is not endorsed or certified by the NVD (NVD terms of use). NVD descriptions over 1,000 characters are shortened and marked as shortened by Bosco Labs. - deps.dev (existence check only): its data is "available under a CC-BY 4.0 license" and the API is used under the Google API Terms of Service (deps.dev); only a yes/no is used.
